# 마을 반복 작업 점검 — 2026-10-25

매 프레임 실행되는 코드와 그 호출 경로를 확인해 포탑 탐색·발사구 조회, 산소 아이콘 및 은행·포탑 관리 창의 불필요한 반복 작업을 줄였습니다.

- `Turret`는 타깃이 없을 때 매번 `FindObjectsByType<Villan>`으로 씬 전체를 조회했습니다. 이제 `Villan`의 활성화·비활성화에 맞춰 유지하는 목록에서 후보를 확인합니다. 플레이 시작 때 한 번 재구성해 씬 재로드를 끈 경우도 처리합니다. 범위 판정과 기존 우선순위, 타깃 재탐색 시점은 유지합니다.
- 발사구 유무 확인은 임시 목록을 만들지 않고 첫 유효 항목에서 끝냅니다. 발사 코루틴의 발사구 인덱스 목록도 재사용합니다. 유무 확인이 발사 중인 목록을 비우지 않도록 분리했습니다.
- `O2Icon`은 저장 산소 수량이나 표시 텍스트가 바뀔 때만 숫자 문자열을 만듭니다. 부유 애니메이션과 입력 처리는 계속 실행합니다.
- `BankUI`와 `TurretUI`는 가격·업그레이드 가능 상태가 그대로면 문자열을 다시 만들지 않습니다. 포탑 버튼의 자식 텍스트 조회도 가격을 갱신할 때만 합니다. 산소 잔액 및 탄약 변화에 따른 구매 가능 여부는 계속 반영하고, 창을 다시 열면 표시를 갱신합니다.

## 비교 측정

Apple M2, Unity 6000.2.14f1의 독립된 임시 프로젝트에서 실제 TURRET1 프리팹과 관리 UI를 사용했습니다. 각 경로를 워밍업 후 2,000회 호출했습니다. 포탑 탐색 후보는 10개입니다.

| 경로 | 수정 전 GC 할당 발생 횟수 | 수정 후 | 수정 전 시간 | 수정 후 시간 |
| --- | ---: | ---: | ---: | ---: |
| 포탑 타깃 탐색 | 4,000 | 0 | 14.862 ms | 7.915 ms |
| 포탑 발사구 목록 조회 | 4,000 | 0 | 0.360 ms | 0.023 ms |
| 같은 값의 산소 수량 표시 | 2,000 | 0 | 0.226 ms | 0.028 ms |
| 같은 값의 은행 가격 표시 | 4,000 | 0 | 0.620 ms | 0.067 ms |
| 같은 값의 포탑 관리 표시 | 16,000 | 0 | 3.570 ms | 0.347 ms |

할당은 현재 스레드의 `GC.Alloc` 프로파일러 표본 Count 합계이며 바이트 수가 아닙니다. 이 환경의 `GC.GetAllocatedBytesForCurrentThread`는 생성이 있는 경로에서도 증가하지 않아 비교에 사용하지 않았습니다. 표의 시간은 2,000회 반복의 합계이며 한 프레임의 시간이나 전체 게임 FPS가 아닙니다. 마을 전체 렌더링·GPU 비용 또는 장시간 메모리 누수를 측정한 결과도 아닙니다.

## 검증

`VillagePerformanceTests`의 4개 검사에서 반복 할당 제거, 범위·우선순위에 따른 타깃 선택, 적의 비활성화·재활성화·파괴·풀 복귀, 발사구 참조 변경, 산소 수량·은행 레벨·탄약·구매 가능 상태 변화와 창 재열기를 확인했습니다.

기존 가산 씬의 마을 풀 정리 검사, 외부 UI로 전환할 때 배달 내용을 유지하는 검사, 상점이 열린 동안 월드 입력을 막고 닫으면 복구하는 검사도 통과했습니다. 총 7개의 관련 검사를 확인했습니다.
