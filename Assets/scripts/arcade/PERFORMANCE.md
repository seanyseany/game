# 아케이드 성능 점검 — 2026-10-21

## 씬 이동 후 남는 작업

- `VillageManagement`가 모든 씬에서 마을 복원과 디버그 호스트 검색을 예약하던 경로를 수정했습니다. 이제 실제 마을 컴포넌트가 있는 씬에서만 실행하고, 같은 씬에 대한 두 로드 콜백은 한 번만 처리합니다. 마을을 떠나면 진행 중인 준비 코루틴과 디버그 프록시를 정리합니다. 디버그 호스트 탐색은 에디터에서만 0.25초 간격으로 수행합니다.
- 마을 저장 데이터가 매 프레임 다시 복원되는 현상이나 UI 이벤트의 중복 누적은 확인되지 않았습니다. 실제 Village ↔ arcade 1 왕복 3회 검사에서 아케이드의 마을 UI 구독 수는 매번 0이었습니다. 저장 데이터는 유지됩니다.

- 마을의 `Villan`·`TurretBullet` 정적 풀에서 언로드된 오브젝트 참조를 제거합니다. 다른 가산 로드 씬의 살아 있는 항목은 유지합니다.
- `BloodSpawner`가 반환된 혈구를 꺼내지 않고 계속 새 혈구를 만들던 경로를 수정했습니다. 수정 전 100회 생성·반환에서 서로 다른 혈구 100개가 만들어졌습니다. 이제 기존 혈구를 재사용하고 재시도 때도 파괴하지 않고 반환합니다.
- `ObjectPool`이 원래 등록된 태그로만 반환하고, 중복 반환을 무시하도록 수정했습니다. 잘못된 태그로 한 오브젝트가 두 풀에 들어가는 문제가 재현됐습니다. 수정 후 200회 재사용에서도 인스턴스 수가 늘거나 서로 같은 인스턴스를 꺼내지 않습니다. 풀 제거 시 소유한 오브젝트도 정리합니다.
- 마을과 아케이드가 기본 데스크톱 프레임 제한을 함께 관리합니다. 마을 입력 오브젝트가 사라지는 순간 아케이드가 무제한 렌더링으로 돌아가지 않습니다. 이미 지정한 FPS·VSync와 모바일 기본값은 유지합니다.

## 추가 점검: 움직임의 미세 끊김

## 일반 페이즈와 머신건 탑승의 차이 추가 점검

머신건 탑승 중에는 일반 플레이어의 지면 확인·이동·공격 경로가 생략되고 다음 일반 페이즈의 스폰도 대기합니다. 이것만으로 충돌 개수가 원인이라고 단정할 수는 없습니다. 임시 에디터의 일반 진행 측정에서 `Player.OnCollisionStay2D`는 평균 약 0.0016 ms, 최대 약 0.0068 ms였고, 입력 경로는 평균 약 0.012 ms였습니다. 같은 월드에서 탑승 상태의 입력 생략 조건으로 바꿔도 물리 비용 자체는 사라지지 않았습니다. 실제 사용자 에디터의 렌더링 병목을 배제한 결과는 아닙니다.

### 로프와 페이즈의 이동 주기

실제 stage 4-21의 로프 9개로 스크롤을 재현했습니다. 보간을 켜도 부모 Transform을 매 Update에서 움직이면 자식 Rigidbody2D의 보간 이력이 무효화됐습니다. 부모를 멈춘 대조 조건에서는 표시 각도의 정지가 0%였고, 이동하는 부모에서는 약 16.6%였습니다.

- `SwingMotor`의 기본 물리 보간을 켭니다. 이미 지정한 다른 모드는 보존합니다.
- `Mover`에 로프가 있고 자체 Rigidbody2D가 없는 경우, 런타임 Kinematic 루트로 물리 스텝에서 스크롤합니다. 중첩된 고정점·톱니의 물리 원점도 같은 거리만큼 옮깁니다. 속도·토크·물리 스텝은 유지합니다.
- Rigidbody2D 배열은 Awake에서 한 번 캐시합니다. 분리되거나 비활성화된 물체는 스크롤 대상에서 제외합니다. 일반 Transform 이동 페이즈는 기존 방식으로 움직입니다.
- 풀 재활성화는 새 스폰 위치로 옮기고, 컴포넌트만 잠시 껐다 켤 때는 지연된 표시 좌표를 물리 좌표로 복사하지 않습니다.

`ArcadeObstacleMotionTests`는 게임 루프의 PreLateUpdate 끝에서 표시 각도를 읽습니다. 에디터 테스트 러너가 렌더 보간 전에 재개되는 경우를 피합니다. 최종 6초 검사에서 움직임 3,195개 표본 중 표시 각도의 정지는 0개였습니다. 36 유닛 스크롤, 고정점·톱니의 실제 이동, 일시 정지·재활성화 위치도 함께 검사합니다. 표시 각도 반복률이며 FPS 드롭률은 아닙니다.

### 진행 중 최초 생성

다음 스테이지의 프리팹을 플레이 도중 한 프레임에 하나씩 만들던 경로에서, 단일 복제가 약 12 ms까지 걸렸습니다. 이제 첫 페이즈를 시작하기 전에 등록된 페이즈들의 초기 풀 준비를 완료합니다. `initialPoolSizePerPrefab` 수량과 최대 풀 크기는 바꾸지 않습니다. 후반 페이즈의 대기 인스턴스를 더 일찍 보유하는 방식이므로 시작 시 메모리 사용과 준비 시간은 늘 수 있으며, 무제한으로 미리 생성하지 않습니다.

원본 arcade 1 설정의 18초 점프·공격 22회 검사에서 준비된 인스턴스는 시작과 끝 모두 103개였고, 진행 중 `Arcade.CreatePhase` 호출은 0회였습니다. 두 검사에서 프레임 시간 p95는 약 16.8 ms였지만 최대값은 각각 17.25 ms와 38.00 ms로 달랐습니다. 초기 복제 비용을 옮긴 결과와 로프 보간 개선이 확인됐으며, 모든 에디터 끊김이 사라졌다는 뜻은 아닙니다.

2D 물리 측정은 `ProfilerCategory.Physics2D`로 바로잡고 유효한 호출 표본을 기록합니다. 마지막 두 실행에서 물리 호출 중앙값은 약 1.10/0.41 ms, 최대값은 5.15/12.24 ms였습니다. 장면·접촉 상태와 에디터 스케줄링이 달라 단일 최대값을 충돌량에 따른 고정 비용으로 해석하지 않습니다. 로프·실제 폭탄 충돌·점프 공격·씬 왕복·풀 재사용을 포함한 17개 검사가 통과했고, 정지·재활성화 보정 후 관련 10개 항목도 다시 통과했습니다.

## Bomb: 감속 중 로프 타깃 통과 보완

타깃 Transform을 물리 동기화 전에 옮기는 재현 검사에서 기존 폭탄이 화면상의 타깃을 지나도 폭발하지 않았습니다. 반대로 Rigidbody의 위치가 화면 보간보다 먼저 바뀌는 경우도 있어 한쪽 좌표만 쓰면 충분하지 않았습니다. 감속 자체가 모든 통과 현상의 원인이라는 뜻은 아니며, 서로 다른 갱신 시점에 의존하던 판정 경로를 보완했습니다.

- 원형 로프 타깃에는 폭탄 캡슐과 원의 상대 이동 경로를 직접 계산합니다. 화면 위치와 물리 위치의 이전·현재 기록을 각각 유지하며 서로 섞지 않습니다. 타깃이 폭탄을 지나치는 경우도 처리하고, 확인된 명중은 즉시 기존 폭발·피해 처리로 연결합니다.
- X만 비교하지 않고 Y 거리, 폭탄의 회전·오프셋·두께, 타깃 반지름을 포함합니다. 정확한 X 일치에 의존하지 않으며, 위아래로 떨어진 타깃의 X만 교차할 때는 폭발하지 않습니다. 비원형 타깃은 기존 형상 캐스트를 유지합니다.
- 이동 업데이트 이후 폭탄을 처리합니다. 기본 Trigger 폭탄은 발사 때 전체 ObstacleInfo 검색·충돌 무시 등록을 하지 않고, 지정된 타깃만 검사합니다. 타깃 수집은 재사용 List로 바꾸고 트리거 콜백의 부모 Collider 배열 생성도 제거했습니다. 전역 SyncTransforms 호출은 추가하지 않았습니다.
- 타깃의 충돌체가 전부 비활성화되면 남아 있는 빈 RopeAnchor 피벗을 계속 추적하지 않고 폭탄을 정리합니다.

`BombCollisionTests` 12개가 통과했습니다. 물리 동기화 전 화면 타깃 이동, 물리 좌표가 먼저 이동한 타깃, 고속·저프레임 이동, X만 교차하는 오폭 방지, 비원형 타깃, 재타깃·풀 재사용을 포함합니다. 실제 stage 4-21 배치의 로프 9개를 대상으로 접촉 감속→밀림→회복 중 비행도 검사했습니다. 이 검사는 실제 기본 프레임 제한과 같은 60fps에서 실행합니다.

임시 Unity 6000.2.14f1 에디터에서 워밍업 후 타깃 지정+원형 타깃 비행 판정 2,000회는 관리 힙 할당 0 B, 약 7.28 ms였습니다. 동일 프레임 내 반복 경로의 측정이며 전체 게임의 FPS 수치는 아닙니다.

### 탐지 전·타깃 지정·발사 후 추가 점검 (2026-10-22)

기존 충돌 검사는 타깃을 직접 지정했으므로 실제 SawDetector→BombLauncher 경로를 검사하지 않았습니다. 이번에는 실제 탐지기·런처·폭탄·머리 풀과 stage 4-21 로프를 연결한 검사를 추가했습니다.

- 탐지 전: 장전 대기나 쿨다운 중 들어온 톱니는 OnTriggerEnter가 한 번 지나가면 재탐지되지 않았습니다. 감속으로 탐지 영역에 오래 머물러도 마찬가지였습니다. OnTriggerStay에서 발사 가능 여부를 다시 확인합니다.
- 탐지 시: 이미 폭탄이 날아가는 타깃을 Collider별로 예약해 재시도 때문에 같은 톱니에 탄약을 연속 소비하지 않게 합니다. 폭발·풀 반환·재타깃·파괴 때 예약을 해제합니다. 풀 스폰이 실패하면 머리와 탄약을 보존합니다. 기존 무작위 타깃 선택과 10초 고정 좌표 발사 규칙은 유지합니다.
- 발사 후: 2D 비행에 타깃 Z 깊이가 섞여 XY 이동 속도를 줄이던 부분을 제거하고 폭탄 Z는 보존합니다. Rigidbody 보간 이후 LateUpdate에서 표시 타깃을 따라가며 기존 화면·물리 상대 경로 충돌 검사를 유지합니다.

수정 전 새 재현 검사 3개(깊이 차이, 쿨다운 중 진입, 장전 전 진입)가 모두 실패했습니다. 수정 후 새 검사 10개와 기존 충돌 검사 12개, 총 22개가 통과했습니다. 실제 접촉 감속을 탐지 전·타깃 지정 직후·비행 중 각각 시작하는 경로도 통과했습니다. 추가로 비행 중 중복 발사 방지, 풀 실패 시 탄약 보존, 예약 수명, 고정 좌표 자동 발사를 확인합니다. 임시 프로젝트에서 실행했으며 원본 에디터의 재현 장면을 직접 관찰한 결과는 아닙니다.

타깃 예약은 재사용 사전에 보관하고 해제하며 전역 씬 검색이나 SyncTransforms를 추가하지 않았습니다. 기존 2,000회 타깃 지정·비행 반복의 관리 힙 할당 0 B 검사도 통과했습니다.

### 같은 X줄의 무작위 한 발 규칙 복구

위의 OnTriggerStay 재시도는 선택된 타깃만 제외했으므로 같은 탐지 줄의 나머지 톱니도 차례로 발사 대상으로 만들었습니다. 감속으로 한 줄이 탐지기에 오래 머무는 동안 더 뚜렷해지는 회귀입니다. 같은 X의 톱니 3개를 정지시킨 재현에서 수정 전 탄약 3개를 소비했습니다.

이제 트리거 진입·이탈로 접촉 묶음을 유지하고, 다음 물리 스텝에서 겹친 후보 중 하나를 무작위로 고릅니다. 성공한 묶음은 선택된 톱니가 파괴되거나 폭탄이 반환된 뒤에도 소비 상태를 유지하며, 묶음이 모두 빠져나가면 다음 줄을 받을 수 있습니다. 장전·쿨다운 중 진입의 재시도는 보존합니다. OnTriggerStay 콜백을 제거했고, 대기는 탐지기당 0.05초 간격으로 확인합니다. 발사한 묶음에는 겹침 검색을 반복하지 않습니다. 불필요한 추가 폭탄과 폭발 처리도 줄어듭니다.

같은 줄에서 탄약 1개만 소비하고 나머지 톱니 2개를 유지하는 검사, 다음 줄의 재발사, 기존 감속·비행 검사를 포함한 23개가 통과했습니다. 이는 임시 에디터의 회귀 검사 결과이며 사용자 에디터의 전체 프레임 시간을 측정한 결과는 아닙니다.

별도 무작위 선택·버퍼 재사용 검사도 통과했습니다(총 24개). 워밍업 후 같은 X의 후보 3개에 대해 2,000회 선택한 결과 모두 선택 가능했고 관리 힙 할당은 0 B, 반복 총 시간은 약 2.99 ms였습니다. 이 수치는 선택 함수의 반복 측정이며 전체 게임의 렉이 사라졌음을 뜻하지 않습니다.

### 남은 탄의 강제 발사: 분노 발동 기준으로 변경 (2026-10-24)

stage 4-21의 정상 속도 재현에서 1~3번째 탄은 실제 로프를, 4~6번째 탄은 런처 활성화 약 10.5초 후 고정 좌표를 타깃으로 잡았습니다. RopeAnchor (15)·(16)을 여섯 번째 탄에 직접 지정한 별도 검사에서는 둘 다 명중했습니다.

사용자 요청에 따라 런처 진입 시 시작하던 타이머를 제거했습니다. 이제 GameData.OnRageStart를 받은 시점부터 rageForcedFireDelay(기본 2초)를 기다린 뒤 현재 남은 탄을 등록 좌표로 일괄 발사합니다. 일반 발사는 실제 탐지 타깃을 계속 사용합니다. BombLauncher 프리팹과 TRAIN의 해당 설정도 2초로 맞췄습니다. 진입 중 분노가 발동하면 타이머를 다시 시작하지 않고, 시간이 지났을 경우 진입 완료 즉시 발사합니다. 초기화·비활성화 시 대기 코루틴과 이벤트 구독을 정리하며, 집에 대기 중인 새 장전 탄은 이전 분노로 강제 발사하지 않습니다.

분노 전 타이머가 시작되지 않는지, 실제 분노 발동 2초 후 발사하는지, 진입 중 발동, 초기화에 따른 취소, 활성화 반복 시 구독 수와 기존 충돌·연기·풀 동작을 포함한 39개 검사가 임시 프로젝트에서 통과했습니다.

## 시작부터 느껴지는 미세 끊김 점검 (2026-10-25)

사용자가 구분한 증상은 오래 플레이할수록 심해지는 지연이 아니라 시작부터 일정하게 느껴지는 미세 끊김입니다. 현재 기본 Quality는 VSync 0이며 `GameplayFramePacing`이 데스크톱에 소프트웨어 60fps 제한을 적용합니다. 확인 당시 `UserSettings/Layouts/default-6000.dwlt`와 `CurrentMaximizeLayout.dwlt`의 Game 뷰 VSync도 꺼져 있었습니다. Unity는 데스크톱에서 소프트웨어 제한에 의한 미세한 표시 간격 불균형이 가능하므로 VSync를 권장합니다: [Application.targetFrameRate](https://docs.unity3d.com/6000.2/Documentation/ScriptReference/Application-targetFrameRate.html).
